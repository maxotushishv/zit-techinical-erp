# Technical Group ERP — MVP

ქართული ვებაპლიკაცია ერთი ადმინისტრატორისთვის: პროდუქტები, კლიენტები, შეთავაზებები, ინვოისები, PDF/ბეჭდვა, მოგების მიმოხილვა.

## 1. Supabase
1. Supabase Dashboard → Authentication → Users: დარწმუნდით, რომ ადმინისტრატორი შექმნილია.
2. Supabase Dashboard → SQL Editor: გახსენით `supabase.sql`.
3. შეცვალეთ `REPLACE_WITH_YOUR_ADMIN_EMAIL` **ზუსტად იმ ელფოსტით**, რომლითაც შექმენით მომხმარებელი.
4. გაუშვით SQL. ბოლო SELECT-მა უნდა დააბრუნოს **ერთი ჩანაწერი**. თუ არ დააბრუნა, არ გააგრძელოთ, სანამ ელფოსტას არ გაასწორებთ.
5. Authentication → Providers → Email: გამორთეთ **Allow new users to sign up** (თუ ჩართულია), რადგან სისტემა მხოლოდ თქვენთვისაა.

## 2. ლოკალურად გაშვება
1. დააკოპირეთ `.env.example` → `.env`.
2. ჩაწერეთ Supabase-ის **Publishable Key** `VITE_SUPABASE_PUBLISHABLE_KEY`-ში. Publishable Key საჯაროა; **არასოდეს** ჩაწეროთ service_role ან secret key.
3. ტერმინალში: `npm install` და `npm run dev`.
4. გახსენით მითითებული ლოკალური მისამართი, შედით ადმინისტრატორის ელფოსტითა და პაროლით.

## 3. Vercel
1. ატვირთეთ პროექტი GitHub-ზე, დააკავშირეთ Vercel-თან.
2. Framework: Vite. Build command: `npm run build`. Output: `dist`.
3. Environment Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`.
4. Deploy.

## როგორ მუშაობს
- პროდუქტში ინახება შესყიდვის/გასაყიდი ფასი, მარაგი და გარანტიის თვეები.
- შეთავაზებაში/ინვოისში პოზიციების ფასები ინახება იმ მომენტის ასლად: მოგვიანებით პროდუქტის ფასის ცვლილება ძველ დოკუმენტს არ ცვლის.
- PDF: გახსენით დოკუმენტი → პრინტერის ღილაკი → ბრაუზერში **Save as PDF**.
- შესყიდვის ფასი **არ იბეჭდება** კლიენტის დოკუმენტზე.
- Dashboard-ის შემოსავალი/მოგება ითვლება მხოლოდ **გადახდილი** ინვოისებიდან; ეს არის სავარაუდო მთლიანი მოგება და არა საგადასახადო/ბუღალტრული წმინდა მოგება.

## MVP-ის შეზღუდვები (მნიშვნელოვანია)
- ეს არის სამუშაო საწყისი ვერსია, **არა** დასრულებული ბუღალტრული ან საგადასახადო პროგრამა.
- მარაგის ავტომატური ჩამოწერა და ნაწილობრივი გადახდები ჯერ **არ არის** განხორციელებული.
- ფასდაკლება, დღგ, ხარჯები, ტრანსპორტირება და საგადასახადო აღრიცხვა სრულად არ არის მოდელირებული.
- დოკუმენტის ნომერი დროის ნიშნულით იქმნება, არა კანონით დადგენილი უწყვეტი სერიით.
- დოკუმენტის ფორმაში ჯერ **არ არის** შეყვანილი თქვენი რეალური საიდენტიფიკაციო კოდი, ბანკის რეკვიზიტები და ლოგო; ბეჭდვაში ამ ველებს დროებითი ტექსტი აქვს.
- დოკუმენტის შეცვლა/წაშლა შესაძლებელია; საბოლოო იურიდიული/აუდიტის რეჟიმისთვის საჭიროა უცვლელი ჩანაწერები და აუდიტის ჟურნალი.
- ბრაუზერის ბეჭდვა გამოიყენება PDF ექსპორტად; სერვერული PDF ჯერ არ არის.

## უსაფრთხოება
- მხოლოდ ავტორიზებული ადმინისტრატორი იღებს მონაცემებს RLS-ით.
- არასოდეს განათავსოთ Supabase secret/service_role key ბრაუზერში.
- ადმინისტრატორის პაროლი არ გაუზიაროთ სხვებს; რეკომენდებულია MFA, რეგულარული სარეზერვო ასლები.
